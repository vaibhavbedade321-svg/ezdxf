Add a semantic version bump recommendation to griffe.

Griffe can list the breaking changes between two versions of a package, but it never turns that into a release decision and never notices backward-compatible additions. Release tooling wants a single answer: is the next release a major, minor or patch bump.

`recommend_bump(old, new, ignore=())`, importable from `griffe` alongside `Bump`, `ChangeKind` and `BumpReport`, compares two loaded package models and returns a `BumpReport`. Objects are compared by the path they are exposed under, relative to the package name: a re-exported object is tracked under its exported name rather than where it is defined, and nested members of classes and submodules, including containers reached through a re-export, are compared too. Names listed in `ignore`, matched on the first path segment, are excluded entirely, breaking changes included. `bump_between(package, old_path, new_path, ignore=(), **load_options)` loads the package from each search path, forwarding the loading options to both loads, and compares them.

A breaking change or a public object that left the public surface recommends `Bump.MAJOR`. A public object added, an object that gained a backward-compatible capability, or a public object newly carrying a `deprecated` decorator recommends `Bump.MINOR`. Anything else, including private additions and docstring-only edits, recommends `Bump.PATCH`. The compatible capability gains are a function signature that only added optional parameters or a new variadic or relaxed an existing required parameter to optional, a class that only added bases, and an object that declared a return or type annotation it previously lacked. Deleting a public object or changing its kind is reported once, as `BREAKING`, under the exported path, never also as a removal; the `REMOVED` kind captures a public object that leaves the surface without a breakage being reported, such as a name dropped from `__all__` while still defined.

Each reported change exposes a `kind` (one of `BREAKING`, `REMOVED`, `ADDED`, `EXPANDED` and `DEPRECATED`), a `path`, a non-empty `detail`, and a `severity` giving the bump level that change alone would force. `BumpReport` carries `bump`, the `breaking` list and a `changes` list sorted by path then kind. It exposes `additions`, `removals`, `expansions` and `deprecations` path lists, `counts` mapping kind values to nonzero counts, a `changes_of_kind(kind)` filter and `changelog()` grouping changes by their first path segment. `render_text()` and `render_markdown()` name the level and list the changed paths, while `explain()` and `str()` give the same one-line summary naming the level. `gated_by(level)` accepts a `Bump` member or its string value; `bump_version(version)` bumps a `major.minor.patch` version, dropping any suffix and raising `ValueError` on malformed input; and a JSON-serializable `as_dict()` carrying `bump`, `breaking`, `additions`, `removals`, `expansions`, `deprecations`, `counts` and `changes` entries with each change's kind, path and detail.

`griffe semver PACKAGE --old OLD --new NEW` prints the level with its changes, JSON with `--json`, Markdown with `--markdown`, or with `--bump VERSION` that version bumped, exiting nonzero on a malformed version. `--fail-on LEVEL` exits nonzero when the recommendation meets that level, `--ignore NAME` is repeatable, and the common loading flags are accepted and forwarded to the loader. Enum members carry lowercase string values.
