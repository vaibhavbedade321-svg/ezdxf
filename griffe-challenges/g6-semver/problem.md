Add a semantic version bump recommendation to griffe.

Griffe can list the breaking changes between two versions of a package, but it never turns that into a release decision, and it never notices backward-compatible additions at all. Release tooling wants a single answer: is the next version a major, minor or patch bump.

`recommend_bump(old, new)`, importable from `griffe` alongside `Bump`, `ChangeKind` and `BumpReport`, takes two loaded models of the same package and returns a `BumpReport`. Objects are compared by their path relative to the package name, so the recommendation does not depend on the name each version was loaded under, and nested members of classes and submodules are compared too. `bump_between(package, old_path, new_path, **load_options)` is a convenience that loads the package from each search path and compares the two.

A breaking change, a removed public object, or a public object whose kind changed between function, class and attribute recommends `Bump.MAJOR`. A public object added, or a public function whose signature gained only optional parameters or a new variadic without breaking callers, recommends `Bump.MINOR`. Anything else, including private additions and docstring-only edits, recommends `Bump.PATCH`. A change already reported as breaking is not counted a second time as a removal or kind change.

`BumpReport` carries `bump`, a `breaking` list, and a `changes` list of `Change` records sorted by path then kind, each with a `kind` (a `ChangeKind`), a `path` and a `detail`. It exposes `additions`, `removals` and `expansions` path lists, a `counts` mapping from change-kind member names to counts omitting empty kinds, a `changes_of_kind(kind)` filter, `render_text()` and `render_markdown()` renderers that describe an empty delta in one line, `gated_by(level)` telling whether the recommendation meets a threshold, `explain()` and `str()` giving a one-line summary, and `bump_version(version)` returning a `major.minor.patch` string bumped by the level, dropping any suffix and raising `ValueError` on a malformed version. `as_dict()` is JSON-serializable through the same mechanics as the other model types.

`griffe semver PACKAGE --old OLD --new NEW` prints the recommended level with its changes, a JSON report with `--json`, Markdown with `--markdown`, or with `--bump VERSION` that version bumped. `--fail-on LEVEL`, taking a lowercase level name, exits nonzero when the recommendation meets that level. The `Bump` and `ChangeKind` members carry lowercase string values.
