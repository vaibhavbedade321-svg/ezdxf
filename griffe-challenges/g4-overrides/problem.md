Add an override compatibility check to griffe.

Griffe compares two package versions for breaking changes, but within one version it cannot flag an override that cannot substitute for the method it replaces.

`check_overrides(package)`, importable from `griffe` along with `OverrideIssue` and `OverrideIssueKind`, walks every class of a loaded package, including nested classes and classes in submodules, and compares each method or attribute against the nearest definition it overrides in the method resolution order. It returns `OverrideIssue` records carrying a `kind`, the `method_path` of the overriding member and the `base_path` of the overridden one, sorted by method path. Each has a JSON-serializable `as_dict()` keyed by `kind`, `method_path` and `base_path`, and an `explain()` returning a one-line message naming both paths and the incompatibility; `str()` returns the same. `kind` is an `OverrideIssueKind` member; its string `.value` is what `as_dict()`, the JSON output and `explain()` carry.

The `OverrideIssueKind` categories are `PARAMETER_REMOVED` when a parameter of the overridden method is no longer accepted, `PARAMETER_ADDED_REQUIRED` when the override adds a parameter without a default, `PARAMETER_CHANGED_KIND` when a parameter can no longer be passed by keyword or no longer positionally, `PARAMETER_NOW_REQUIRED` when a parameter lost its default, `PARAMETER_MOVED` when positional parameters were reordered, `VARIADIC_REMOVED` when a variadic disappeared, `FLAVOR_CHANGED` when a staticmethod or classmethod is overridden by a different flavor, `KIND_CHANGED` when a method is overridden by an attribute or property or the reverse, and `SETTER_REMOVED` when a writable property is overridden by a read-only one.

Issues are counted per incompatibility, never deduplicated by kind: an override that drops both `*args` and `**kwargs` yields two separate `VARIADIC_REMOVED` records. Flavor and kind changes suppress further signature comparison for that pair. A disappearing parameter is not an issue when a variadic absorbs it: `*args` absorbs a positional-only parameter, `**kwargs` a keyword-only one, and a parameter passable either way needs both. Positional-only parameters are matched by position rather than by name, so renaming one is compatible; every other parameter is matched by name. Adding a parameter with a default is compatible, and plain attributes overriding attributes are not compared. `__new__` counts as a staticmethod and `__init_subclass__` and `__class_getitem__` as classmethods whether or not they carry the decorator, and their implicit first parameter is ignored, as for regular methods and classmethods. Name-mangled methods are skipped, and a class whose bases cannot be resolved is skipped rather than failing the whole check.

A name inherited from several ancestors without being redefined is checked too: the definition the resolution order picks is compared against each same-named definition it shadows, with the shadowing definition as the method path. An identical incompatibility reached through several classes is reported once.

`griffe overrides PACKAGE` prints one line per incompatibility naming both paths to standard error, or a JSON array with `--json` to standard output, and exits nonzero exactly when incompatibilities exist. A repeatable `--kind KIND` option, taking lowercase hyphenated kind names, restricts which kinds are reported.
