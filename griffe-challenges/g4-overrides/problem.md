Add an override compatibility check to griffe.

Griffe can compare two versions of a package for breaking changes, but within a single version it has no way to flag a subclass that overrides a method with a signature that cannot substitute for the one it replaces.

A `check_overrides(package)` function, importable from the top-level `griffe` package along with `OverrideIssue` and `OverrideIssueKind`, walks every class of a loaded package, including nested classes and classes in submodules, and compares each method or attribute against the nearest definition it overrides in the class's method resolution order. It returns `OverrideIssue` records carrying a `kind`, the `method_path` of the overriding member and the `base_path` of the overridden one, sorted by method path, with a JSON-serializable `as_dict()` keyed by `kind`, `method_path` and `base_path`, and an `explain()` method returning a human-readable message naming both paths and the incompatibility; `str()` of an issue returns the same message. `kind` is an `OverrideIssueKind` member; its string `.value` is what `as_dict()`, the JSON output and `explain()` carry.

The categories in `OverrideIssueKind` are `PARAMETER_REMOVED` when a parameter of the overridden method is no longer accepted, `PARAMETER_ADDED_REQUIRED` when the override adds a parameter without a default, `PARAMETER_CHANGED_KIND` when a parameter can no longer be passed by keyword or can no longer be passed positionally, `PARAMETER_NOW_REQUIRED` when a parameter lost its default value, `PARAMETER_MOVED` when positional parameters were reordered, `VARIADIC_REMOVED` when `*args` or `**kwargs` disappeared, `FLAVOR_CHANGED` when a staticmethod or classmethod is overridden by a different flavor of method, `KIND_CHANGED` when a method is overridden by an attribute or property, or an attribute by a method, and `BASE_CONFLICT` when a class inherits the same method name from several bases without overriding it and the definition winning the method resolution order cannot substitute for a later one; the conflict is reported at the inheriting class's path for each incompatible later definition, and only regular instance methods participate: dunder methods, staticmethods and classmethods are not considered for conflicts. Flavor and kind changes suppress further signature comparison for that pair. A parameter that disappears is not an issue when a variadic in the override absorbs it. Adding a parameter with a default is compatible. Attributes overriding attributes are not compared. The implicit first parameter of regular methods and classmethods is ignored, class-private name-mangled methods are skipped, and a class whose bases cannot be resolved is skipped rather than failing the whole check.

`griffe overrides PACKAGE` prints one line per incompatibility mentioning both paths to standard error, or a JSON array with `--json` to standard output, and exits nonzero exactly when incompatibilities exist. A repeatable `--kind KIND` option, taking lowercase hyphenated kind names, restricts which kinds are reported.
