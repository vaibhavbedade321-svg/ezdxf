Add an override compatibility check to griffe.

Griffe compares two package versions for breaking changes, but within one version it cannot flag a subclass whose override has a signature that cannot substitute for the method it replaces.

`check_overrides(package)`, importable from `griffe` along with `OverrideIssue` and `OverrideIssueKind`, walks every class of a loaded package, including nested classes and classes in submodules, and compares each method or attribute against the nearest definition it overrides in the method resolution order. It returns `OverrideIssue` records carrying a `kind`, the `method_path` of the overriding member and the `base_path` of the overridden one, sorted by method path. Each has a JSON-serializable `as_dict()` keyed by `kind`, `method_path` and `base_path`, and an `explain()` returning a one-line message naming both paths and the incompatibility; `str()` returns the same message. `kind` is an `OverrideIssueKind` member; its string `.value` is what `as_dict()`, the JSON output and `explain()` carry.

The `OverrideIssueKind` categories are `PARAMETER_REMOVED` when a parameter of the overridden method is no longer accepted, `PARAMETER_ADDED_REQUIRED` when the override adds a parameter without a default, `PARAMETER_CHANGED_KIND` when a parameter can no longer be passed by keyword or no longer positionally, `PARAMETER_NOW_REQUIRED` when a parameter lost its default, `PARAMETER_MOVED` when positional parameters were reordered, `VARIADIC_REMOVED` once per variadic that disappeared, so an override dropping both `*args` and `**kwargs` reports it twice, `FLAVOR_CHANGED` when a staticmethod or classmethod is overridden by a different flavor, and `KIND_CHANGED` when a method is overridden by an attribute or property or the reverse.

Flavor and kind changes suppress further signature comparison for that pair. A disappearing parameter is not an issue when a variadic absorbs it: `*args` absorbs a positional-only parameter, `**kwargs` a keyword-only one, and a parameter passable either way needs both. Adding a parameter with a default is compatible, and attributes overriding attributes are not compared. The implicit first parameter of regular methods and classmethods is ignored, name-mangled methods are skipped, and a class whose bases cannot be resolved is skipped rather than failing the whole check.

`griffe overrides PACKAGE` prints one line per incompatibility naming both paths to standard error, or a JSON array with `--json` to standard output, and exits nonzero exactly when incompatibilities exist. A repeatable `--kind KIND` option, taking lowercase hyphenated kind names, restricts which kinds are reported.
