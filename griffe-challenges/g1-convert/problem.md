Griffe parses Google, Numpydoc and Sphinx docstrings into structured section models, but the pipeline is strictly one-directional: there is no way to turn a parsed docstring back into text. That blocks an often requested workflow, migrating a whole package from one docstring dialect to another.

The top-level `griffe` package exposes `compose`, which takes parsed sections and a target dialect named by a `Parser` member or its string name, along with `compose_google`, `compose_numpy` and `compose_sphinx` handling one dialect each and a `composers` mapping from `Parser` members to composer callables, one entry per concrete dialect. Composing with the `auto` style raises `ValueError`, while composing an empty section sequence yields text rather than raising. Each composer renders annotations in its dialect's native syntax, and numpy composition renders a parameter default as `name : type, default=value`, so both survive reparsing.

For any docstring parsed with a dialect, composing its sections in that same dialect and reparsing yields an equal section model, and composing again yields identical text. When the composed output contains at least one section the target dialect expresses natively, `infer_docstring_style` classifies it as that dialect. Sections a dialect cannot express are preserved with their content intact rather than dropped, in a form that keeps composition stable. In the dialects that render section headings, a section whose model carries an explicit title keeps that title in the composed heading instead of the canonical one.

`rewrite_source(source, module, style, source_style=None)`, also importable from `griffe`, returns the source with every docstring, on the module and recursively on all its members, replaced by its composition in the target style. Indentation, string prefixes and quote characters are preserved, and a docstring written with a single quote of either character widens to a triple quote of that same character, never the other one, only when the rewritten docstring spans multiple lines. Every byte outside the docstring literals is untouched, including trailing comments on the closing line, and the rewritten source always remains valid Python even when the composed text contains the current delimiter. A raw-string docstring is left unchanged rather than corrupted when its converted text cannot be represented in a raw literal at all, as happens when that text ends with an odd number of backslashes. When `source_style` is omitted the style of each docstring is inferred.

`griffe convert PACKAGE -t STYLE` converts a package's docstrings: `--in-place` writes files back, `--diff` prints a unified diff without writing, `--check` writes and prints nothing and exits nonzero exactly when files would change, and `-d` forces the style existing docstrings are parsed with.
