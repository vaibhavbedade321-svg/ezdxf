Griffe already models a package's public surface - its objects, their definition and exported paths, `__all__` lists and re-export chains - but never checks that surface for the hygiene problems those models make visible. Add an audit that finds and reports them.

`audit_surface(package)`, importable from `griffe` with `SurfaceIssueKind`, resolves re-export chains and returns a report whose issues expose `kind`, `public_path` and `details`. Categories: `PRIVATE_ORIGIN`, a public name defined in a private module, details naming the definition and, if multiply exposed, the canonical path; `DANGLING_EXPORT`, an `__all__` entry resolving to nothing; `UNDOCUMENTED`, a public module, class or function lacking a docstring; `DUPLICATE_EXPOSURE`, reported once at the canonical path with the other paths in details; `CYCLIC_ALIAS`; `PRIVATE_LEAK`, a public signature or base referencing a private-module object that is not itself publicly reachable; `INCONSISTENT_ALL`, a name a module's `__all__` omits; `MUTABLE_DEFAULT`, a public function or method whose signature carries a list, dict or set default argument. A public class or module reached through a re-export is traversed so its own public members are audited under that public path, while a private origin is reported once at the re-export entry. Private objects yield nothing.

The report holds issues sorted by category name then path, `issues_of_kind(kind)` listing that category's issues in that same order, `counts` keyed by member names covering only kinds with issues, `canonical_paths` from definition path to shortest public path with ties alphabetical, `render_text()` and `render_markdown()` renderers that group issues by category under a heading built from that category's `SurfaceIssueKind` value and list the `public_path` of every issue in the group, `render_text()` giving each category its count, both saying clean when empty, and JSON-serializable `as_dict()` with `package`, issues and both mappings. It also offers `filter(*kinds)` returning a report over only those categories, `affected_paths` listing the distinct issue paths sorted, and a `summary()` naming the package.

`griffe api PACKAGE` exits 1 when issues exist and 0 otherwise. The default text report and `--markdown` both write to standard error and only when issues exist, so a clean run prints nothing there; `--json` always writes the JSON report to standard output, carrying an empty issue list on a clean run. Repeatable `--fail-on` takes hyphenated category names and, when given, restricts the nonzero exit to runs where any one of the selected categories is present.
